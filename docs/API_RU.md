# Nitoryu для авторов плагинов: C++ API

*English version: `API.md`.*

если ваш мод это только данные, этот файл не нужен, все есть в `FCS_RU.md`. этот для тех, кто пишет свой плагин под RE_Kenshi и хочет, чтобы он работал вместе с Nitoryu: спросить, дерется ли персонаж двумя клинками, какой у него ранг, и узнавать, когда второй клинок попал или отбил удар.

это версия API 1: чтение, события, правило пары, которое дает аддону открывать свои пары (тяжелое оружие с саблей, два древковых) со своими числами, и фильтр приемов, который говорит, какими приемами пара пользуется. своих анимаций для пары в ней еще нет, так что двуручная пара пока играет анимации Nitoryu для двух клинков.

рядом с этим файлом: `NitoryuApi.h`, весь API в одном заголовке на C. в репозитории с исходниками это `src/api/NitoryuApi.h`, а `examples/NitoryuAddonSample` это маленький аддон, который использует все, что ниже.

## Что можно, а что пока нет

| Нужно | Данные (`FCS_RU.md`) | API |
|---|---|---|
| Пустить оружие в пару или не пустить | Да: поле WEAPON, два списка оружия | Не нужен |
| Заставить своих NPC драться двумя клинками, задать им навык | Да | Не нужен |
| Добавить прием для парного боя | Да | Не нужен |
| Узнать в плагине, что персонаж дерется двумя клинками, его ранг, путь, парный бой | Нет | Да: `isDual`, `getInfo` |
| Реагировать, когда второй клинок попал, отбил удар, начался особый прием, сменился ранг | Нет | Да: `subscribe` |
| Прочитать настройку Nitoryu, как она действует сейчас | Нет | Да: `getSetting` |
| Пустить в пару тяжелое или древковое оружие | Нет, данными никогда | Да: `registerPairRule` |
| Запретить пару или пустить пару любых категорий, со своими числами веса, скорости и урона | Частично (запись, списки) | Да: `registerPairRule` |
| Сказать, какими приемами пара может пользоваться | Да: поле `nitoryu move weapons` у приема | Да: `registerMoveFilter` |
| Свои анимации для пары | Нет | Позже |

## Как плагин подключается

ваш аддон это отдельный мод: своя папка, свой `RE_Kenshi.json`, Nitoryu в обязательных предметах в Мастерской. порядок загрузки двух модов не важен.

вы экспортируете одну функцию, а Nitoryu ее вызывает:

```cpp
#include "NitoryuApi.h"

static const NitoryuApi* g_nitoryu = NULL;

extern "C" __declspec(dllexport) void __cdecl NitoryuAddon_Init(const NitoryuApi* api)
{
    if (api == NULL || api->version < 1)
        return;
    g_nitoryu = api;        // живет, пока игра не закрыта
    api->subscribe("My addon", NITORYU_EV_ALL, &onEvent, NULL);
}
```

Nitoryu ищет `NitoryuAddon_Init` в каждом загруженном плагине, один раз, в главном цикле, когда все плагины уже загружены и его настройки прочитаны. так что искать DLL Nitoryu самому не надо, и не важно, как эта DLL называется в сборке.

когда Nitoryu не установлен, выключен, или игрок отключил аддоны, вашу функцию никто не вызовет. `g_nitoryu` тогда остается NULL, и плагин должен работать без него.

**плагин, которому надо только иногда спросить** (без событий), может обойтись без экспорта: объявите `NITORYU_API_FIND` перед подключением заголовка (после `<windows.h>` и `<tlhelp32.h>`) и вызовите `Nitoryu_FindApi(1)`. она находит Nitoryu по его экспорту `Nitoryu_GetApi`. пока Nitoryu не готов (первые кадры игры), она возвращает NULL, так что спросите позже еще раз, не запоминайте NULL.

## Правила

- **Только C.** Никаких классов и `std::string` через границу. Все функции `__cdecl`.
- **Игровые объекты это `void*`**: `Character*`, `Weapon*`. Они должны быть живыми, проверить указатель Nitoryu не может.
- **Текст возвращается в ваш буфер**: `getVersion(buf, sizeof(buf))`. Функция возвращает `NITORYU_OK` (0) или больше, если все получилось, и отрицательный `NITORYU_E_*`, если нет. Исключений нет.
- **Структура, которую вы передаете, начинается с `size`.** Перед вызовом поставьте `info.size = sizeof(info)`. Так аддон, собранный со старым заголовком, работает с новым Nitoryu.
- **Таблица только растет.** Новые функции идут в конец, ничего не сдвигается и не пропадает. Что вам нужно, проверяйте по `api->version`.
- **Потоки.** У каждой функции ниже написано, откуда ее можно звать. Ваш обработчик событий всегда вызывается в главном цикле.
- **Если ваш обработчик упал**, Nitoryu это ловит, больше его в этой сессии не вызывает и пишет в лог `api_callback_fault addon='...'`. Игра идет дальше.

коды ошибок: `NITORYU_E_ARG` (NULL, неизвестный ключ, маленький буфер), `NITORYU_E_OFF` (Nitoryu выключен или аддоны отключены), `NITORYU_E_THREAD` (только главный цикл), `NITORYU_E_BUSY` (вы спросили изнутри своего правила пары или фильтра приемов), `NITORYU_E_FULL` (нет места: 64 подписки, 16 правил пары, 16 фильтров приемов), `NITORYU_E_FAULT` (ошибка внутри Nitoryu, вызов ничего не сделал).

## Функции

все они поля `NitoryuApi`, с версии API 1 (Nitoryu 1.2.0).

| Функция | Поток | Что делает |
|---|---|---|
| `int getVersion(char* out, unsigned outSize)` | любой | Версия Nitoryu, например `1.2.0`. Возвращает длину |
| `int isDual(void* character)` | любой | 1 = персонаж прямо сейчас дерется двумя клинками, 0 = нет |
| `int getInfo(void* character, NitoryuInfo* out)` | любой | Состояние персонажа, ниже |
| `const char* reasonName(int reason)` | любой | Короткое имя для `NitoryuReason` (`two_handed_only`), для вашего лога. Строка постоянная, держите ее сколько хотите |
| `int getSetting(const char* fcsKey, char* out, unsigned outSize)` | главный цикл | Значение настройки текстом по ее ключу в FCS (`nitoryu weapon categories`), как оно действует сейчас: по умолчанию, из FCS какого-то мода или из ini игрока. Ключи в `FCS-settings.md`. Возвращает длину |
| `int invalidate(void* character)` | любой | Nitoryu ненадолго запоминает состояние персонажа. Вызовите, когда что-то ваше изменило то, каким оно должно быть, и на следующий вопрос ответ будет свежим |
| `int subscribe(const char* addonName, int eventType, NitoryuEventFn fn, void* userData)` | любой | Ваша `fn` вызывается на каждое событие этого типа, `NITORYU_EV_ALL` на все. `addonName` попадает в лог, если в обработчике что-то пошло не так. Отписаться нельзя |
| `int registerPairRule(const char* addonName, NitoryuPairRuleFn fn, void* userData)` | любой | Вашу `fn` спрашивают про каждую пару, «Правило пары» ниже. Убрать его нельзя |
| `int registerMoveFilter(const char* addonName, NitoryuMoveFilterFn fn, void* userData)` | любой | Вашу `fn` спрашивают про каждый прием, который выпал паре, «Фильтр приемов» ниже. Убрать его нельзя |

"прямо сейчас" в `isDual` значит, что стойка включена: два оружия, которые идут в пару, одно из них в руках, обе руки целы, а у персонажа игрока еще и не выключена кнопка стойки. боец с клинками в ножнах не считается (`not_drawn`).

### NitoryuInfo

```cpp
NitoryuInfo info;
info.size = sizeof(info);
if (g_nitoryu->getInfo(character, &info) == NITORYU_OK && info.dual)
    ...
```

| Поле | Что |
|---|---|
| `dual` | 1 = прямо сейчас дерется двумя клинками |
| `reason` | Почему нет, `NitoryuReason`: `NOT_DRAWN`, `LAYOUT` (не два на спине и не спина + пояс), `HANDS_NOT_IN_PAIR`, `WEAPON_REFUSED`, `TYPE_NOT_ALLOWED`, `TWO_HANDED_ONLY`, `NO_BARE_MESH`, `ARM`, `TOGGLED_OFF`, `RACE_REFUSED`, `NPC` (NPC не дотягивает до минимумов или не включен), `GAME_VERSION`, `NOT_READY`, `OTHER`. `DUAL`, когда дерется |
| `rank` | 0-5, после всех ограничений. 0, когда не дерется двумя |
| `pathRank` | Ранг, который дает один только путь |
| `path` | Путь, 0-100. 0, когда не дерется двумя |
| `dualWielding` | Навык парного боя, как в окне характеристик. Заполнен и когда не дерется двумя |
| `dualWieldingInFight` | Он же после перегруза и брони, это число идет в бой |
| `offFromHip` | 1 = второе оружие с пояса |
| `optedIn` | 1 = NPC, которого включил какой-то мод |
| `mainWeapon`, `offWeapon` | `Weapon*`: то, что в руках, и второе. NULL, когда не дерется двумя |

## События

```cpp
void __cdecl onEvent(const NitoryuEvent* ev, void* userData)
{
    if (ev->type == NITORYU_EV_OFF_HAND_HIT)
        ...     // ev->character попал по ev->other оружием ev->weapon
}
```

обработчик вызывается в главном цикле, примерно через кадр после самого момента, так что в нем можно писать в лог, трогать свой интерфейс и звать API. цена этого: игра к тому времени уже ушла дальше. события одного кадра приходят в том порядке, в котором случились.

| Событие | `character` | Остальное |
|---|---|---|
| `NITORYU_EV_DUAL_ON` | кто теперь дерется двумя клинками | `value` = его ранг |
| `NITORYU_EV_DUAL_OFF` | кто больше не дерется | `value` = `NitoryuReason`, `text` = ее имя. Убрать клинки в ножны это тоже `DUAL_OFF`. Приходит примерно через 0.6 с после самого момента: в бою стойка иногда пропадает на мгновение, и об этом не сообщается |
| `NITORYU_EV_RANK_CHANGED` | боец | `value` = новый ранг, `amount` = старый |
| `NITORYU_EV_DUAL_WIELDING_CHANGED` | боец | `amount` = навык сейчас. Приходит, когда навык переходит через целое число, пока боец дерется двумя |
| `NITORYU_EV_OFF_HAND_HIT` | атакующий | `other` = по кому попал, `weapon` = второе оружие, `value` = вид приема (1 удар, 2 двойной, 3 добивающий, 4 с дистанции, 0 прием другого мода), `text` = его трек анимации. Только попавшие удары |
| `NITORYU_EV_OFF_HAND_PARRY` | защищающийся | `other` = атакующий |
| `NITORYU_EV_SPECIAL` | боец | Выбран добивающий прием или прием с дистанции. `value` = вид, `text` = метка приема (`cross`, `dash`, `spin`, или имя вида для приема другого мода) |
| `NITORYU_EV_CHARACTER_GONE` | число, уже не персонаж | Персонаж, о котором вы получали события, уничтожен (загрузка, убранное тело). Указатель не читайте, просто выбросьте то, что храните для него |

`text` никогда не NULL и живет только внутри обработчика, скопируйте, если нужен потом.

Nitoryu начинает следить за персонажем, когда тот первый раз дерется двумя клинками, так что `DUAL_ON` это всегда первое, что вы о ком-то услышите. когда аддон подписывается посреди игры, `DUAL_ON` придет по каждому бойцу, который в этот момент дерется двумя, как только Nitoryu посмотрит на него снова.

очередь держит 256 событий между двумя кадрами. сверх этого новые выбрасываются и считаются (`api_events_dropped` в строке `counts` лога).

## Правило пары

какие два оружия дерутся как пара, решает правило самого Nitoryu: запись оружия, список категорий (из коробки катаны и сабли), кнопка игрока «любое оружие» (дробящее и рубящее). правило пары это слово вашего плагина в этом:

```cpp
void __cdecl pairRule(const NitoryuPairQuery* q, NitoryuPairAnswer* a, void* userData)
{
    bool heavyA = q->categoryA == 3, heavyB = q->categoryB == 3;
    int other = heavyA ? q->categoryB : q->categoryA;
    if (heavyA == heavyB || (other != 0 && other != 1))
        return;                             // нет мнения
    a->answer = NITORYU_PAIR_ALLOW_TWO_HANDED;  // тяжелое оружие с катаной или саблей
    a->attackSpeed = 0.9f;
}
```

| Ответ | Что делает |
|---|---|
| `NITORYU_PAIR_DEFAULT` | Нет мнения. Ответ таким и приходит, так что правило, которому все равно, просто возвращается |
| `NITORYU_PAIR_ALLOW` | Пара, какие бы ни были категории. Но не с двуручным оружием |
| `NITORYU_PAIR_REFUSE` | Не пара (причина `plugin_refused`) |
| `NITORYU_PAIR_ALLOW_TWO_HANDED` | Пара, в том числе с тяжелым или древковым оружием |

порядок, решает первое совпадение:

1. Оружие, которое запрещено своей записью или списком (`nitoryu dual wield` = 2), в пару не идет никогда, что бы ни сказало правило. Последнее слово за автором оружия.
2. Правило, ответившее REFUSE, запрещает пару. Если аддонов несколько: первое, в порядке регистрации.
3. Иначе первое правило, ответившее ALLOW или ALLOW_TWO_HANDED, пускает пару, и считаются его числа.
4. Иначе правило самого Nitoryu.

**двуручное оружие** (тяжелое, древковое) идет в пару только через ALLOW_TWO_HANDED. ни настройка, ни значение в записи, ни список, ни кнопка «любое оружие» этого не делают: эта кнопка только для дробящего и рубящего, и для пары, которую пустило ваше правило, она не показывается. луки в пару не идут никогда.

что остается в силе после ALLOW: одно из двух оружий в руках, у второго есть меш `bare sword`, обе руки целы, раса не запрещена, игрок не выключил стойку, а NPC по-прежнему проходит свои минимумы или включен.

**числа.** когда ваш ответ пускает пару, четыре множителя идут в формулы самого Nitoryu для этой пары, каждый приходит как 1.0:

| Поле | Что умножает |
|---|---|
| `weight` | Вес пары в правиле силы и скорости (веса двух оружий x `nitoryu pair weight mult`). Меньше 1 = пара считается легче |
| `attackSpeed` | Множитель скорости атаки пары |
| `blockSpeed` | Множитель скорости блока пары |
| `offHandDamage` | Урон второго оружия |

значение вне 0.1-10 считается как 1.0. можно ответить ALLOW с числами и для пары, которую Nitoryu пускает и так, например чтобы катана с коротким клинком была быстрее. так и надо балансить свою пару: если хукать те же функции игры, что и Nitoryu, результат зависит от того, какой из двух плагинов загрузился первым.

запрос: `allowed` и `reason` это ответ самого Nitoryu без плагинов, `categoryA` / `categoryB` категории оружия в игре (0 катана, 1 сабля, 2 дробящее, 3 тяжелое, 4 рубящее, 8 древковое), `twoHandedA` / `twoHandedB`, `player`, и указатели `character`, `weaponA`, `weaponB`. A и B это два оружия на персонаже без порядка, правило спрашивают и когда они в ножнах (кнопка стойки, окно характеристик), так что отвечайте одинаково на (A, B) и (B, A).

**обработчик вызывается сразу на месте**, в том потоке, который спрашивает (главный цикл, боевые потоки), несколько раз за кадр для персонажа на экране. поэтому:

- он короткий: прочитали запрос, заполнили ответ, вернулись
- никаких вызовов игры, которые могут ждать, никаких блокировок, которые может держать другой ваш поток, никакого лога на каждый вызов
- не спрашивайте Nitoryu изнутри него: `isDual`, `getInfo` и `invalidate` там возвращают `NITORYU_E_BUSY`
- если правило зависит от чего-то вашего, что поменялось (переключатель в вашем интерфейсе), вызовите после этого `invalidate(character)`

как выглядит двуручная пара: для оружия в правой руке игра играет свои анимации, а стойка, блоки, доставание и приемы у Nitoryu сделаны под два клинка. анимаций для тяжелой пары в Nitoryu нет. эта часть API (свой набор анимаций для пары) будет позже.

## Фильтр приемов

приемы бойца с двумя клинками это записи COMBAT_TECHNIQUE с полем `nitoryu move` (`FCS_RU.md`, «Свой прием для парных клинков»), мои и других модов. сказать, какая пара каким приемом пользуется, можно двумя способами.

**данными, без плагина:** поле `nitoryu move weapons` у приема, список категорий оружия (`1,3` = сабли и тяжелое). прием используется только парой, у которой оба оружия есть в списке. пусто = любая пара. так что свои приемы аддона для пары тяжелое + сабля несут `1,3`, и никому другому они не достаются.

**фильтром**, для того, что данными не сказать (у моих приемов список пустой, поэтому они достаются любой паре):

```cpp
int __cdecl moveFilter(const NitoryuMoveQuery* q, void* userData)
{
    if (q->twoHandedPair && q->kind == NITORYU_MOVE_TWIN)
        return NITORYU_FILTER_REFUSE;       // никаких двойных ударов с тяжелым оружием
    return NITORYU_FILTER_DEFAULT;
}
```

порядок, решает первое совпадение: фильтр, ответивший `NITORYU_FILTER_REFUSE` (прием этой парой не используется), фильтр, ответивший `NITORYU_FILTER_ALLOW` (используется, что бы ни говорил список записи), потом список записи.

запрос: `kind` (1 удар, 2 двойной, 3 добивающий, 4 с дистанции), `mainHand` (удар одним оружием, которое в руках), `categoryMain` / `categoryOff`, `twoHandedPair` (пара пущена ответом ALLOW_TWO_HANDED), `listed` (что говорит про эту пару список самой записи), указатели `character`, `mainWeapon`, `offWeapon`, `record` (`GameData*` приема) и две строки, которые живут только внутри обработчика: `recordId` (`9-Nitoryu.mod`) и `track`.

он вызывается сразу на месте, как правило пары, с десяток раз на атаку, и правила те же: коротко, без вызовов игры, без вопросов обратно к Nitoryu. если фильтр запретит все приемы, боец бьет только основным оружием.

про собственные приемы игры для оружия в руках фильтр не спрашивают: при включенном «только удары Nitoryu» (по умолчанию) боец с двумя клинками ими не пользуется, а при выключенном их выбирает игра. для двуручной пары меняется одно: длинный двуручный прием другого мода, который Nitoryu у обычной пары забирает (левая рука не может взяться за рукоять), остается, это прием самого оружия (счетчик `two_handed_kept_pair`).

## Что видно в логе

`RE_Kenshi_log.txt`, сразу как игра дошла до первых кадров:

- `api_config addons=1 api_version=1 found=N subscriptions=M pair_rules=R move_filters=F`: API открыт, найдено N аддонов. `addons=0`: игрок (или сборка) отключил аддоны.
- `api_addon module='YourAddon.dll' subscriptions=K pair_rules=R move_filters=F init='ok'`: ваша `NitoryuAddon_Init` отработала. `init='fault'`: она упала.
- `api_pair_rule addon='...' answer=3 category_a=3 category_b=1 own_allowed=0 weight=... attack_speed=...`: правило решило про пару. одна строка на каждое разное решение (правило, две категории, ответ). answer: 1 пустить, 2 запретить, 3 пустить с двуручным.
- `api_callback_fault addon='...' kind='event' event=N` (или `kind='pair_rule'`, `kind='move_filter'`): обработчик упал и выключен до конца сессии.
- счетчики: `pick_skip_plugin_filter` (фильтр запретил прием), `pick_skip_move_weapons` (запретил список записи), `api_pair_allowed`, `api_pair_two_handed`, `api_pair_refused` (на каждый пересчет стойки бойца), `api_pair_no_weapon_skill` (пару пустили с категорией, для которой в игре нет навыка оружия: не считается), `api_events_dropped`, `api_callback_fault`.

игрок может отключить все аддоны через `[Compat] addons=0` в `Nitoryu.ini` (сборка: настройка `nitoryu addons` в GLOBAL CONSTANTS). это для баг-репортов, чтобы понять, чей баг. читается один раз, при запуске.

## Пример аддона

`examples/NitoryuAddonSample` в репозитории с исходниками: один `.cpp`, проект под Visual C++ 2010 (та же настройка, что у самого Nitoryu, `BUILDING.md`), `RE_Kenshi.json`.

1. `startPlugin` только пишет строку: Nitoryu может быть еще не загружен, поэтому там ничего не спрашивается.
2. `NitoryuAddon_Init` запоминает таблицу, читает версию Nitoryu и одну настройку, подписывается на все события и регистрирует правило пары и фильтр приемов.
3. `onEvent` пишет строку на каждое событие и спрашивает `getInfo` про персонажа, кроме `CHARACTER_GONE`.
4. `pairRule` пускает тяжелое оружие в пару с саблей или катаной, чуть легче и чуть медленнее.
5. `moveFilter` забирает у этой пары двойные удары.

чтобы попробовать: соберите его, сделайте папку мода `NitoryuAddonSample` в `Kenshi\mods` с DLL, `RE_Kenshi.json` и пустым `NitoryuAddonSample.mod` (делается в FCS, без него лаунчер мод не покажет), поставьте галочку выше или ниже Nitoryu, достаньте две катаны и подеритесь. в логе пойдут строки `NitoryuAddonSample:`. потом тяжелое оружие и саблю на спину: появится кнопка стойки, и они дерутся как пара.

## Версии и что я обещаю

- имена, поля и порядок в таблице остаются как есть. новое добавляется в конец, с большим `NITORYU_API_VERSION`.
- аддон, собранный под API 1, работает с любым более новым Nitoryu. в обратную сторону проверяете вы: `api->version` для нужной функции, `ev->size` и `info.size` для поля, которое добавила более поздняя версия.
- тип события, которого вы не знаете, это не ошибка, просто пропустите его.
